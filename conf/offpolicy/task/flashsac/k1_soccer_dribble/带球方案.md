## 0. 课程场景布局（共线 +X）

`scene_soccer_dribble_minimal.xml` 中三点共线（沿世界 **+X**）：

| 点 | 世界坐标 (x, y) | 间距 |
|----|-----------------|------|
| 机器人起点（keyframe） | **(0, 0)** | — |
| **一阶段终点**（小半透明球，**绿→红**） | **(1, 0, z≈0.57 m)** | 距起点 **1 m** |
| 足球初位置 | **(1.2, 0)** | 距一阶段终点 **0.2 m** |

起点与足球处**无**额外标记。一阶段球由 `phase1_waypoint_marker_pending` / `_reached` 切换显隐（`set_world_geom_pos`）。  
到达判定：机座 **穿过球体**（3D 距球心 ≤ 半径 **0.08 m**）；`contype/conaffinity=0`、`mass=0` 无碰撞。

**奖励分阶段（`soccer_dribble.py`，`phase2_mask = phase1_reached`）：**

| 阶段 | 条件 | 奖励 |
|------|------|------|
| **一阶段** | 未穿过 waypoint 球 | **与 K1WalkFlat FlashSAC 相同**（`g1_walk_flat_flashsac_reward` + owner 步态 override）；`ball_*` / `feet_inward_yaw` / `feet_step_travel` / `termination_bad` **scale×0** |
| **二阶段** | 已穿过 waypoint | 一阶段 walk 项 **保留** + 上表球相关项 **按 scale 生效** |

命令：一阶段 `fixed_cmd_lin_speed` **朝 waypoint**；二阶段 **朝球**。丢球硬终止仅二阶段生效。

常量：`K1_SOCCER_CURRICULUM_*`、`K1_SOCCER_PHASE2_REWARD_KEYS`（`constants.py`）。

## 1. 背景与术语

### 1.1 推进式带球（Push）

球稳定在身前偏前，随机器人向目标方向 **轻推 / 滚动前进**；触球距离中等，类似「带着球走」。

- 球多在身前约 **0.35–0.55 m**
- 允许中等步幅与前进速度
- **当前 `K1SoccerDribble` 奖励设计更接近此模式**

### 1.2 盘拉带球（Pull）

球更 **贴脚**，以拨、拉、扣为主的小范围控球；前进可较慢，强调护球与变向，而非大脚往前踢再追。

- 球多在脚边约 **0.15–0.35 m**
- 允许适度横向与短暂「拉回」速度分量
- **需新 task / 新 reward 分叉，不宜与 Push 共用一套 scale 硬调**

### 1.3 与平地走的关系

| 阶段 | 任务 | 作用 |
|------|------|------|
| 基础 | `K1WalkFlat` | 站稳、迈步、姿态 |
| 带球 1 | 推进式 `K1SoccerDribblePush` | 身前带球前进 |
| 带球 2 | 盘拉式 `K1SoccerDribblePull` | 贴脚盘拉（可选从 Push checkpoint warm-start） |

## 2. 总体架构

### 2.1 任务拆分（推荐）

```
K1WalkFlat（已有）
    ↓ warm-start
K1SoccerDribblePush      # 推进式（在现有 K1SoccerDribble 上演进）
    ↓ 可选 warm-start
K1SoccerDribblePull      # 盘拉式（新 task + 新 owner）
```

| 注册名 | 说明 |
|--------|------|
| `K1SoccerDribble` | 现阶段可视为 **Push**；后续可别名化为 `K1SoccerDribblePush` |
| `K1SoccerDribblePull` | **新建**：盘拉专用 reward、初态、命令、owner YAML |

**不推荐**：单一 env + Hydra 开关在两套 reward scale 间切换——调参与 TensorBoard 难复盘，易混。

### 2.2 共用不变量（两模式均保持）

- 机器人：**22 DOF**，`k1.xml`，每脚 **4** 个 `foot_contact_*` 传感器（scene 内 8 路聚合）
- 场景：`scene_soccer_dribble_minimal.xml`，地面碰撞 **`COL_Collider`**（非平地 `floor` plane）
- 球：**free joint**，无 ball action；`sim_dt = 0.002`（Motrix 稳定）
- 训练栈：FlashSAC + motrix（代表 owner）；reward 经 `run_reward_dispatch`
- **不** 为带球改 `K1WalkFlat` 的 obs（带球独立任务）

### 2.3 与平地走的主要差异（带球共性）

详见 `任务分析.md`。摘要：

- Obs：**单帧 78 维**（AMP 布局 + 球 3 维），**无 gait_phase**、无历史堆叠；Walk 为单帧 77 维且含 phase
- 命令：每步 **朝球** `_command_toward_ball`，非随机 `vel_limit`
- Reset：固定 keyframe + qvel=0；球初位置在场景 XML 中给定

## 3. 推进式带球（Push）

### 3.1 行为规格（验收标准）

| 指标 | 目标 |
|------|------|
| 球–机座水平距离 | **0.40–0.50 m**（对齐 `ball_keep_distance`） |
| 球相对位置 | 身体前方扇区（`ball_front`） |
| 球速 | 与前进一致；平面速度 **≤ ~0.35 m/s**（`ball_speed_cap`） |
| 机器人 | 少摔、少绕圈、少髋 Roll 侧摆 |

### 3.2 奖励策略（在现有项上收敛）

**主目标（保持 / 微调 scale）：**

- `ball_progress`、`ball_keep`、`ball_front`
- `ball_speed_match`、`ball_moving`、`ball_approach`

**约束：**

- `ball_lost`、`ball_over_speed`、`ball_orbit`
- `feet_inward_yaw`、`termination_bad`

**行走栈：**

- 维持当前 **弱 scale** 的 walk 项（`tracking_lin_vel` 等）
- `feet_step_travel` 保持 **中高**，鼓励迈步

**Obs / 命令（当前）：**

- **单帧** 78 / critic 81（无历史堆叠）；AMP 布局 + `rel_x, rel_y, rel_vx`（球 3 维）
- `fixed_cmd_lin_speed ≈ 0.3`，`_command_toward_ball`
- Warm-start 仍从 **K1WalkFlat**（77 维）加载；与带球 78 维差 1 维（球块），`strict: false`

**Owner：** `conf/offpolicy/task/flashsac/k1_soccer_dribble/motrix.yaml`  
**Warm-start：** `K1WalkFlat` FlashSAC 最新 checkpoint（已默认）

### 3.3 训练与验收

**命令：**

```bash
uv run train --algo flashsac --task k1_soccer_dribble --sim motrix
```

**验收（play + log）：**

1. 连续 **≥10 s** 不触发丢球硬终止（`ball_lost_distance_hard`）
2. 球多在身前 **±30°**、距离 **0.3–0.6 m**
3. `ball_orbit`、`ball_over_speed` 均值低；无明显绕圈、爆踢

## 4. 盘拉带球（Pull）

### 4.1 行为规格（验收标准）

| 指标 | 目标 |
|------|------|
| 球–机座水平距离 | **0.20–0.35 m**（明显近于 Push） |
| 触球风格 | 小范围拨、拉、扣；少大脚 |
| 前进 | 可 **慢**（0.15–0.25 m/s）；控住优先于推进 |
| 横向 | 允许适度 `rel_y` / 拉球分量；惩罚大绕圈 |

### 4.2 奖励策略（相对 Push 分叉）

**建议新增 term（代码层 2–3 项）：**

| 项（建议名） | 作用 |
|--------------|------|
| `ball_close` | 距离 < `ball_pull_distance`（如 **0.28 m**）时高斯奖励 |
| `ball_pull_back` | 球偏远时，奖励机体系 **`rel_vx_b < 0`** 的拉回（带 cap） |
| `ball_lateral_control` | （可选）惩罚过大 `\|rel_y\|`，或奖励适度横向 |

**相对 Push 削弱：**

- `ball_progress`、`ball_speed_match` **降 scale**
- `ball_keep_distance` **改小**（配置字段）

**相对 Push 加强：**

- `ball_over_speed`、`ball_orbit`
- `feet_inward_yaw`

**保留：**

- 弱行走栈 + `feet_phase_contact` / `feet_double_stance`（节奏，不强迫大步）

### 4.3 观测（分两期）

| 期 | 内容 | 说明 |
|----|------|------|
| **一期** | 与 Push **相同** obs（78 / 81） | 实现快；靠 reward 区分，可能学得偏「贴脚慢推」 |
| **二期** | 单帧 **+2～4** 维球特征（如 `rel_y_b`、`rel_vy_b`、`ball_dist_xy`） | 维数变；需新 run 或扩网 warm-start |

### 4.4 命令与初态

| 项 | Pull 建议 |
|----|-----------|
| `fixed_cmd_lin_speed` | **0.15–0.2**（低于 Push 0.3） |
| 球初位置 | keyframe 由 **(1.0, 0, z)** 改为约 **(0.45, 0, z)**（近脚）；改 XML 或 reset 写 qpos |
| Reset | 保持 qvel=0；Pull 稳定后可加球 xy **小随机 ±0.05** |

**Owner（待建）：** `conf/offpolicy/task/flashsac/k1_soccer_dribble_pull/motrix.yaml`  
**Warm-start：** **Push 收敛后** checkpoint（优先于仅从 Walk）

### 4.5 训练与验收

**命令（规划）：**

```bash
uv run train --algo flashsac --task k1_soccer_dribble_pull --sim motrix
```

**验收：**

1. 球多数时间在 **0.15–0.35 m** 脚边
2. 可见拉/扣（球相对 body 有横向与短暂后向分量）
3. 能缓慢向前；丢球率低于 Push **初训** 阶段即可作为 P2 通过

## 5. 实施阶段

| 阶段 | 内容 | 产出 |
|------|------|------|
| **P0** | 平地走 FlashSAC 稳定（`k1_walk_flat` mujoco 调参） | 可 warm-start 的 `K1WalkFlat` |
| **P1** | **Push**：固化现有 `K1SoccerDribble` owner / reward，motrix 训通 + play | Push 基准视频、log |
| **P2** | **Pull**：`K1SoccerDribblePull` + 新 reward + 近球初态 + owner | 首版可训 |
| **P3** | Pull obs 扩展（若 P2 不够「贴脚盘拉」） | 新 obs 维 + 训练 run |
| **P4** | 文档与命令固化；两模式对比表更新 | 本目录文档 + CI compose 测试（可选） |

## 6. 待决事项（实施前拍板）

1. **Pull 第一版** 是否必须显式奖励「向后拉球」？
   - **是** → 上 `ball_pull_back`
   - **否** → 仅近球 + 慢命令 + `ball_close`（最快 MVP）

2. **`K1SoccerDribble` 命名** 是否重命名为 `K1SoccerDribblePush`？
   - 重命名需迁移 owner 路径、warm_start、log 目录约定

3. **Pull 训练后端** 是否坚持 motrix-only？
   - 与现 owner 一致；mujoco 带球需单独验证 `sim_dt` / 球接触

## 7. 风险与缓解

| 风险 | 缓解 |
|------|------|
| Pull/Push 同 obs 策略混淆 | P2 先 reward 分叉；不够再做 P3 obs |
| 近球初态接触不稳定 | 小步移球位；保持 `sim_dt=0.002` |
| `feet_phase` 诱导伸膝 / 髋侧摆 | 降 `feet_phase` scale；加大 Hip_Roll pose（参考 walk §8） |
| Pull 改 obs 后 checkpoint 不兼容 | 新 task 名、新 run；Push checkpoint 仅作部分 warm-start |

---

## 8. 默认推荐路线

1. **P0 → P1**：先把 **推进式** 在当前 `k1_soccer_dribble` 上训稳。  
2. **P2**：新建 **盘拉式** `K1SoccerDribblePull`，近球 + `ball_close` + 弱 progress + 慢命令；obs 一期与 Push 相同。  
3. 本文件与 `任务分析.md` 分工：本文 = **产品与阶段方案**；`任务分析.md` = **现有代码与配置事实**。
