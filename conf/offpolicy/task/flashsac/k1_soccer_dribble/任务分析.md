# K1SoccerDribble · 任务分析（vs K1WalkFlat）

> 推进式 / 盘拉式 **分阶段训练方案** 见同目录 [`带球方案.md`](带球方案.md)。  
> **训练墙钟为何慢于平地走** 见 [`训练性能分析.md`](训练性能分析.md)。

训练入口（当前代表 owner）：

```bash
uv run train --algo flashsac --task k1_soccer_dribble --sim motrix
```

实现：`K1SoccerDribbleEnv`（`src/unilab/envs/locomotion/k1/soccer_dribble.py`），继承 `K1WalkEnv` 但覆盖 obs / reset / reward / 终止。  
配置：`conf/offpolicy/task/flashsac/k1_soccer_dribble/motrix.yaml`。

---

## 总览对比（平地走 vs 带球）

| 维度 | K1WalkFlat（FlashSAC mujoco） | K1SoccerDribble（FlashSAC motrix） |
|------|-------------------------------|-------------------------------------|
| 场景 | `scene_flat.xml`，`floor` 平面 | `scene_soccer_dribble_minimal.xml`，`COL_Collider` box 地面 + **足球 free joint** |
| 动作 | 22 维关节目标 | **同样 22 维**（球无 action，靠接触动力学） |
| `action_scale` | 0.35（owner 调参） | **0.15**（更小，带球更稳） |
| 观测帧 | **单帧** 77 / critic 80 | **单帧** 78 / critic 81（推进式，无历史堆叠） |
| 观测布局 | G1 walk：含 **gait_phase(2)** | AMP 布局：**无 gait_phase**；含 **球相对状态(3)** |
| 速度命令 | 随机采样 `vel_limit` | 每步 **`_command_toward_ball`**（朝球 0.3 m/s） |
| Reset | 随机 xy/yaw、随机 base qvel、域随机可关 | **固定 keyframe**、qvel=0、**无**质量/摩擦/推力 DR |
| 课程学习 | owner 开 `curriculum`（惩罚缩放） | owner **未开**；`update_state` 也未接 walk 的 curriculum 日志 |
| 初始高度 | base z≈0.55 | base z≈0.574；球在 (1.2, 0, 0.092) |
| 仿真步长 | `sim_dt=0.005`（recipe） | **`sim_dt=0.002`**（球+box 接触稳定） |
| Warm-start | 无（平地自己训） | **默认从 K1WalkFlat FlashSAC 最新 checkpoint 加载 actor** |
| 足部 contact | 8 路，`geom1=floor` | 8 路同名，**`geom1=COL_Collider`** |
| 额外终止 | 无 | **球水平距离 > ball_lost_distance_hard** |

## 1. 动作（Action）

- **维度**：22（`K1_NUM_ACTION`，与平地走相同关节顺序，见 `constants.py`）。
- **映射**：`target = action * action_scale + default_angles`（继承 `K1WalkEnv.apply_action`）。
- **差异**：
  - 带球 `action_scale: 0.15`（owner），平地走当前 `0.35`。
  - 球 **不占用** action 维；球由 `ball-root` free joint + 脚/地接触推动。

---

## 2. 观测（Obs）

### 2.1 维度

| 组 | 平地走 | 带球 |
|----|--------|------|
| Actor | **77** | **78** |
| Critic | **80** = 77 + linvel(3) | **81** = 78 + linvel(3) |

单帧 78 维组成（带球 `_build_single_frame_obs`，顺序固定）：

| 块 | 维数 | 含义 |
|----|------|------|
| `commands_to_amp_obs(cmd)` | 3 | `[-cmd_x, -cmd_y, -cmd_wz×0.25]`（**不是** walk 的原始 cmd） |
| `ball_obs` | 3 | 机体系：球 `rel_x`, `rel_y`, `rel_vx`（**无 rel_vy**） |
| gravity | 3 | 与 walk 相同缩放习惯 |
| gyro | 3 | ×0.25 |
| joint diff | 22 | `dof_pos - default_angles` |
| joint vel | 22 | ×0.05 |
| last_actions | 22 | 上一步 action |

**与平地走的关键差别**：

- Walk：**无球**；有 **gait_phase(2)**；cmd 为物理速度 3 维；单帧无堆叠。
- Soccer：**有球 3 维**；**无 gait_phase**（步态相位仍在 `info` 里给 reward 用，但 **不进 policy obs**）。
- Soccer：**单帧**（`obs_frame_stack=1`）；旧 5 帧 checkpoint 与当前网络输入不兼容，需重训。

### 2.2 命令在 obs 里的含义

每步 `state.info["commands"] = _command_toward_ball()`：

- 方向：机体系指向球的单位向量（xy）。
- 大小：固定 `fixed_cmd_lin_speed`（owner 默认 **0.3 m/s**），再 clip 到 `vel_limit`（±0.65）。

因此 `tracking_lin_vel` 等奖励跟踪的是 **“朝球走”的命令**，不是随机前进命令。

## 3. 奖励（Reward）

带球在 **`K1WalkEnv` 全套步态/行走项** 上增加 **ball_*** 与足球专用项（`soccer_dribble.py` 里 `update` 到 `_reward_fns`）。

### 3.1 行走项（相对平地 FlashSAC，scale 普遍更小）

| 项 | 带球 scale（motrix owner） | 平地走 FlashSAC（参考） |
|----|---------------------------|-------------------------|
| tracking_lin_vel | 0.3 | 2.0 |
| tracking_ang_vel | 0.25 | 1.5 |
| feet_phase | 0.6 | 5.0 |
| feet_phase_contrast | 0.8 | 1.5 |
| feet_phase_contact | 0.5 | 1.0 |
| pose | -0.05 | -0.5（owner 可 -0.8） |
| alive | 0.2 | 10.0 |
| penalty_orientation 等 | recipe 名（-2.5…） | FlashSAC 用 penalty_* 别名 |

带球 **未** 使用 `g1_walk_flat_flashsac_reward.yaml`，仍保留 `orientation` / `ang_vel_xy` / `action_rate` 等 recipe 名（与平地 FlashSAC 的 penalty 别名体系不同）。

### 3.2 带球专用项（仅 Soccer）

| 项 | scale | 作用（简述） |
|----|-------|----------------|
| ball_progress | 1.7 | 球世界系 +x 前进速度 |
| ball_keep | 1.0 | 球–机座 xy 距离接近 `ball_keep_distance`（0.45） |
| ball_front | 0.25 | 球在前方且横向偏差小 |
| ball_speed_match | 0.6 | 球 vx 与命令 vx 一致 |
| ball_approach | 0.5 | 球偏远时奖励径向靠近 |
| ball_moving | 0.3 | 球平面速度接近 `ball_move_speed_target` |
| ball_still | -0.2 | 球太慢小惩罚 |
| ball_lost | -0.8 | 距离 > `ball_lost_distance`（1.35）线性罚 |
| ball_over_speed | -1.0 | 球速 > `ball_speed_cap`（0.35） |
| ball_orbit | -0.4 | 惩罚绕球切向速度 |
| feet_inward_yaw | -1.4 | 惩罚双脚髋 yaw「朝内」 |
| feet_step_travel | **30.0** | 每步双脚位移（鼓励迈步） |
| termination_bad | -20.0 | 摔倒/过低终止时一次性罚 |

超参见 owner `reward:` 下 `ball_*` 与 `feet_phase_swing_height: 0.06` 等。

### 3.3 仍用足部 contact 的行走奖励

`feet_phase_contact` / `feet_double_stance` 与平地走相同逻辑：

- 8 路 sensor 聚合为左右脚 bool（`LEFT/RIGHT_FOOT_CONTACT_SENSORS`）。
- 与步态相位目标着地/离地比对。

## 4. 课程学习（Curriculum）

| | 平地走 | 带球 |
|--|--------|------|
| owner `env.curriculum.enabled` | **true**（惩罚随 episode 长度缩放） | **未配置** → 默认 **false** |
| 代码 | `K1WalkEnv.__init__` 创建 `PenaltyCurriculum`；`update_state` 在 done 时更新 | 继承 init，但 **`K1SoccerDribbleEnv.update_state` 整段覆盖**，**无** curriculum 日志分支 |
| 实践 | 前期 `penalty_action_rate` 等较弱，利于学走 | 全程固定 reward 权重；靠 **warm-start** 继承走路策略 |

## 5. 初始状态（Reset）

### 平地走（`K1WalkDomainRandomizationProvider`）

- 从 `scene_flat.xml` keyframe `stand`（base z≈0.55）出发。
- 随机 xy 偏移、随机 yaw、**随机 base qvel**（`reset_base_qvel_limit: 0.5`）。
- `gait_phase`：offset_phase 随机初始化。

### 带球（`K1SoccerDomainRandomizationProvider`）

- 从 `scene_soccer_dribble_minimal.xml` keyframe `stand`：
  - 机器人：与 stand _pose 一致（腿弯曲 0.3 等）。
  - 球：世界系 **(1.2, 0, 0.092)**，距一阶段 waypoint **0.2 m**。
- **qvel 全 0**（机器人+球无初速度）。
- reset xy：**仅 x 方向** keyframe (0,0) 上 **±0.5 m** 均匀随机，**y 固定为 0**（共线 +X 课程）。
- **无** 随机 yaw/线速度（`reset_base_qvel_limit: 0.0`）。
- `gait_phase` 固定为 `[0, π]`（左右脚相差 π），reset 后 `reset()` 再写 **朝球命令**。

## 6. 终止条件（Termination）

| 条件 | 平地走 | 带球 |
|------|--------|------|
| 倾倒 | `tilt > max_tilt_deg`（FlashSAC 共享 65°） | **55°**（owner） |
| 机身过低 | `base_z < min_base_height`（0.35） | **0.25**（更低，盘带允许略蹲） |
| 丢球 | — | `‖ball_xy‖ > ball_lost_distance_hard`（**2.8**） |

**注意**：`ball_lost` 是 **reward 惩罚**（阈值 1.35）；**硬终止** 用 2.8。  
`termination_bad` 只在 **摔倒/过低** 时给负奖励，**不包含** 丢球终止。

## 7. 足部 Contact Sensor（与平地走的异同）

### 相同点（都在 `k1.xml`）

- 每脚 **4 个** `foot_contact_{0..3}_geom` 小球。
- Scene 里 **8 个** 同名 sensor：`left_foot_contact_0..3`、`right_foot_contact_0..3`。
- Env 侧：`compute_aggregated_foot_contact` → 左右 bool，供 `feet_phase_contact` / `feet_double_stance`。

### 不同点（仅 scene XML）

| | `scene_flat.xml` | `scene_soccer_dribble_minimal.xml` |
|--|------------------|-------------------------------------|
| 地面碰撞体 | `floor`（plane） | **`COL_Collider`**（厚 box，顶面 z=0） |
| sensor `geom1` | `floor` | **`COL_Collider`** |
| 视觉地面 | 同一 plane | 绿色 `pitch` plane（**仅显示，无碰撞**） |

带球时 contact **只对 box 顶面** 触发，与 Motrix 球 mesh 接触分开；脚感与平地 plane 略有差别，但 **sensor 名字与聚合逻辑与平地走一致**。

## 10. 从平地走过渡到带球时注意

1. **Obs 与 walk 差 1 维**：77（walk）vs 78（带球，多球 3 维、无 gait_phase 2 维）；默认 **warm-start** `strict: false`；旧 390 维 checkpoint 不可用。
2. **先训好 WalkFlat** 再开 `warm_start`（当前默认已开）。
3. 带球 policy **看不到 gait_phase**，步态主要靠 `feet_phase*` reward + `feet_step_travel` 塑形。
4. 调带球优先改 owner 里 **ball_*** / `feet_inward_yaw` / `feet_step_travel`，不要直接抄平地 FlashSAC 的大 scale。
