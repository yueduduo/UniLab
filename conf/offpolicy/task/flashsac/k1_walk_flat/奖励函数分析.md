# K1WalkFlat · FlashSAC 奖励函数分析

任务入口：

```bash
uv run train --algo flashsac --task k1_walk_flat --sim mujoco
# 或 motrix：task 换为 flashsac/k1_walk_flat/motrix
```

环境与实现：`K1WalkEnv`（`src/unilab/envs/locomotion/k1/joystick.py`），注册名 `K1WalkFlat`。

---

## 1. 配置如何拼起来

本目录 owner YAML（`mujoco.yaml` / `motrix.yaml`）通过 Hydra `defaults` 叠加：

| 顺序 | 文件 | 作用 |
|------|------|------|
| 1 | `conf/locomotion/g1_walk_flat_recipe.yaml` | 共享命令、噪声默认、步态频率、`tracking_sigma`、recipe 级 scales 等 |
| 2 | `conf/locomotion/g1_walk_flat_flashsac_reward.yaml` | FlashSAC 平地走 **完整 scales**（与 G1 FlashSAC 一致）；`penalty_*` 与 recipe 中 `orientation` / `ang_vel_xy` / `action_rate` 互斥（后者 scale=0） |
| 3 | 本目录 `mujoco.yaml` / `motrix.yaml` | 机器人标定：`base_height_target`、`min_base_height`、`pose_weights`（22 维）、`feet_phase_swing_height` |

**与 G1 FlashSAC 的差异（仅 owner 层）**

| 字段 | K1（本目录） | G1（`flashsac/g1_walk_flat/mujoco.yaml`） |
|------|----------------|-------------------------------------------|
| `base_height_target` | 0.55 | 0.754 |
| `min_base_height` | 0.35 | 0.3（共享层默认，G1 未覆盖） |
| `feet_phase_swing_height` | **0.06** | 0.09（recipe 默认） |
| `pose_weights` | 长度 22 | 长度 29 |

`reward.scales` 在 compose 后与 G1 FlashSAC **逐项相同**（见第 2 节）；训练日志里的 reward 名称也应一致。

## 2. 总 reward 怎么算

每步在 `K1WalkEnv.update_state` 中调用 `_compute_reward` → `rewards.run_reward_dispatch`（`src/unilab/envs/locomotion/common/rewards.py`）：

```
total_reward = ctrl_dt * Σ_{name ∈ scales}  scale[name] * fn[name](ctx)     （scale == 0 或 fn 未注册则跳过）
```

- 未加权分量写入 `info["log"]["reward/<name>"]`（约每 4 step 打一次均值）。
- 终端里看到的 `penalty action rate` 对应 **`penalty_action_rate`**（scale=-5），不是 `action_rate`（FlashSAC 下 scale=0）。

### 2.1 生效 scales（compose 后）

| scale 名 | 系数 | 实现位置 |
|----------|------|----------|
| `tracking_lin_vel` | 2.0 | `rewards.tracking_lin_vel` |
| `tracking_ang_vel` | 1.5 | `rewards.tracking_ang_vel` |
| `forward_progress` | 0.0 | `rewards.forward_progress`（不参与） |
| `under_speed` | -0.2 | `rewards.under_speed` |
| `upper_body_pose` | -0.05 | `K1WalkEnv._reward_upper_body_pose` |
| `feet_phase` | 5.0 | `K1WalkEnv._reward_feet_phase` |
| `feet_phase_contrast` | 1.5 | `K1WalkEnv._reward_feet_phase_contrast` |
| `feet_phase_contact` | 1.0 | `K1WalkEnv._reward_feet_phase_contact` |
| `feet_double_stance` | -1.0 | `K1WalkEnv._reward_feet_double_stance` |
| `lin_vel_z` | -1.0 | `rewards.lin_vel_z` |
| `base_height` | -120.0 | `rewards.base_height` |
| `pose` | -0.5 | `rewards.weighted_pose`（`pose_weights`） |
| `penalty_close_feet_xy` | -0.5 | `K1WalkEnv._reward_close_feet_xy` |
| `penalty_feet_ori` | -25.0 | `K1WalkEnv._reward_feet_ori` |
| `penalty_ang_vel_xy` | -1.0 | `rewards.ang_vel_xy`（与 `ang_vel_xy` 同一函数） |
| `penalty_orientation` | -10.0 | `rewards.orientation` |
| `penalty_action_rate` | -5.0 | `rewards.action_rate` |
| `alive` | 10.0 | `rewards.alive`（恒为 1） |
| `ang_vel_xy` / `orientation` / `action_rate` | **0.0** | 与上面对应函数相同，**故意关闭**，避免与 `penalty_*` 重复计分 |

### 2.2 其它 reward 超参（非 scale）

| 字段 | K1 FlashSAC 值 | 用途 |
|------|----------------|------|
| `tracking_sigma` | 0.25 | 速度跟踪 exp 奖励宽度 |
| `gait_frequency` | 1.5 | 步态相位推进：`gait_phase_delta = 2π × f × ctrl_dt` |
| `feet_phase_swing_height` | **0.06**（owner） | 步态目标抬脚高度，见第 3 节 |
| `feet_phase_tracking_sigma` | 0.005（FlashSAC 共享） | `feet_phase` / `feet_phase_contrast` 的 exp 分母 |
| `min_forward_speed_for_gait_reward` | 0.05 | 步态类 reward 的速度门控 |
| `max_tilt_deg` | 65.0 | 倾倒终止 |
| `close_feet_threshold` | 0.15 | 双脚过近惩罚 |
| `base_height_target` / `min_base_height` | 0.55 / 0.35 | `base_height` 惩罚与终止高度 |

## 3. `feet_phase_swing_height`（owner 覆盖项）

配置写在 `mujoco.yaml` / `motrix.yaml` 的 `reward.feet_phase_swing_height`。  
**不是**单独一项 log 名称，而是进入下列三个 reward 的 **目标曲线幅度**（单位：米，脚 site 世界系 z）。

### 3.1 目标脚高：`compute_feet_phase_height_targets`

源码：`src/unilab/envs/locomotion/g1/joystick.py`（K1 与 G1 共用）。

- 输入：`info["gait_phase"]` 形状 `(N, 2)`（左/右相位），以及 `swing_height`（K1=0.06，G1 recipe=0.09）。
- 对每个相位用 **三次 Bézier** 在 `0 ↔ swing_height` 之间插值，得到 `left_target`、`right_target`（支撑相≈0，摆动相峰值≈`swing_height`）。

### 3.2 使用该参数的三个 reward

**（1）`feet_phase`（scale=5.0）** — `_reward_feet_phase`

- 读 `left_foot_pos` / `right_foot_pos` 的 z。
- `reward = exp(-(e_left² + e_right²) / feet_phase_tracking_sigma)`，`e = z_foot - z_target`。
- 乘 `_gait_reward_gate(linvel)`：前进速度 &lt; 0.05 m/s 时整项为 0。

**（2）`feet_phase_contrast`（scale=1.5）** — `_reward_feet_phase_contrast`

- 比较 `(z_left - z_right)` 与 `(target_left - target_right)` 是否一致，鼓励交替迈步。

**（3）`feet_phase_contact`（scale=1.0）** — `_reward_feet_phase_contact`

- `compute_feet_phase_contact_targets`：若 `target_z ≤ 0.5 * swing_height` 则期望 **着地**，否则期望 **离地**。
- 与 8 路 foot contact 传感器聚合 bool（`compute_aggregated_foot_contact`）逐脚比对，匹配为 1，左右平均。

K1 设 **0.06 &lt; G1 的 0.09**：目标抬脚更低，着地相位阈值 `0.03 m` 也更低，适合更宽鞋底、相同 reward 栈下的保守摆腿。

### 3.3 与 `feet_double_stance` 的区别

`feet_double_stance`（scale=-1.0）**不**使用 `feet_phase_swing_height`；在前向命令下惩罚双脚同时着地（`left_contact ∧ right_contact`）。

## 4. 按类别的简要逻辑

### 4.1 速度跟踪

- **`tracking_lin_vel`**：`exp(-‖cmd_xy - v_xy‖² / σ)`。
- **`tracking_ang_vel`**：`exp(-(cmd_yaw - ω_z)² / σ)`。
- **`under_speed`**：前进速度低于命令时的归一化缺口（惩罚）。

### 4.2 姿态 / 高度 / 关节

- **`penalty_orientation`**：`gravity_xy` 平方和（倾角惩罚）。
- **`penalty_ang_vel_xy`**：roll/pitch 角速度平方和。
- **`base_height`**：`(z_base - base_height_target)²`。
- **`pose`**：`(q - q_default)²` 按 `pose_weights` 加权（全身）。
- **`upper_body_pose`**：同上，但前 `K1_UPPER_BODY_JOINTS` 维权重置 0（只约束腿为主）。

### 4.3 脚 / 步态（除第 3 节外）

- **`penalty_feet_ori`**：脚四元数 roll/pitch 分量平方和。
- **`penalty_close_feet_xy`**：双脚水平距离 &lt; `close_feet_threshold` 时惩罚。
- **`lin_vel_z`**：垂直线速度平方。

### 4.4 生存与平滑

- **`alive`**：每 env 恒 1，鼓励不终止。
- **`penalty_action_rate`**：`\|a_t - a_{t-1}\|` 类动作变化（`rewards.action_rate`）。

---

## 5. 终止条件（影响 `alive` 与总回报）

`update_state` 中 `terminated` 当：

- 躯干倾角 &gt; `max_tilt_deg`（65°），或
- `base_pos.z < min_base_height`（K1：0.35）。

## 8. 步态质量问题：上身晃、髋侧摆、伸膝抬腿

### 8.1 现象与机制（为何纯调 `feet_phase_swing_height` 不够）

| 现象 | 常见策略（策略在“钻”奖励） |
|------|---------------------------|
| 抬腿时膝几乎伸直 | `feet_phase` 只约束 **脚 site 世界系 z**；伸膝 + 髋 pitch 也能抬高脚，不一定弯膝 |
| 髋 Roll 侧摆 | `Left/Right_Hip_Roll` 外展可把脚抬离地面，同样满足脚高目标 |
| 上身左右晃 | 骨盆随髋 Roll / 躯干 roll 耦合；`penalty_orientation` 不够强或腿在侧向“划弧” |

站立默认角（`K1_DEFAULT_JOINT_ANGLES`）：髋 pitch ≈ -0.15，**膝 pitch ≈ +0.3（弯）**，踝 ≈ -0.15。`pose` 会把关节往默认拉，但 `feet_phase: 5.0` 往往更强，且 **摆动相并不鼓励“比默认更弯”的膝**。

### 8.2 `pose_weights` 与关节索引（22 维，与 `K1_ACTUATOR_JOINT_ORDER` 一致）

| 索引 | 关节名 | 调参意图 |
|------|--------|----------|
| 0–9 | 头、双臂 | 通常保持小权重 |
| 10 | Left_Hip_Pitch | 矢状面迈步，可中等 |
| **11** | **Left_Hip_Roll** | **侧摆：建议大幅提高权重** |
| 12 | Left_Hip_Yaw | 防扭腰，可略提高 |
| **13** | **Left_Knee_Pitch** | 弯膝：见下文（不宜一味加大“贴默认”） |
| 14 | Left_Ankle_Pitch | 中等 |
| **15** | **Left_Ankle_Roll** | 防脚掌外翻，可提高 |
| 16–21 | 右腿对称 | 同左 |

当前 owner 常把 10–21 全设为 `50`，对 **髋 Roll 约束不够突出**，且与 G1 腿段「前几维 5.0、后面 50.0」的模式也不一致。

### 8.3 推荐调参顺序（仅改本目录 `mujoco.yaml` / `motrix.yaml`）

**第一轮（抑制侧摆 + 上身稳，优先试）**

```yaml
env:
  control_config:
    action_scale: 0.35   # 默认 recipe 0.5；减小关节大幅乱动

reward:
  scales:
    penalty_orientation: -15.0    # 默认 FlashSAC -10
    penalty_ang_vel_xy: -1.5
    upper_body_pose: -0.15         # 实际惩罚腿段（见 §4.2），默认 -0.05
    pose: -0.8                     # 全身 pose，略加强
  # 索引 10–21：加强 Roll/Yaw/踝 Roll，膝与髋 pitch 略放松便于弯膝摆腿
  pose_weights: [
    0.01, 2.0, 5.0, 0.01, 5.0, 5.0, 0.01, 2.0, 5.0, 0.01,
    40.0, 200.0, 80.0, 25.0, 40.0, 120.0,
    40.0, 200.0, 80.0, 25.0, 40.0, 120.0
  ]
```

**第二轮（抬腿形态：脚高 vs 伸膝）**

- `feet_phase_swing_height`：不宜过低（如 0.045）；过低时伸膝/侧摆更易凑高度。建议 **0.07–0.09** 试起，配合上面髋 Roll 惩罚。
- `feet_phase_tracking_sigma`：可略放宽到 `0.008`（recipe 默认），减轻“硬抬高度”。
- 保持 `feet_phase_contrast` / `feet_phase_contact` 开启（FlashSAC 已有），避免双脚乱蹭地。

**第三轮（训练动态，与 `调参日志.md` 一致）**

- 确认 `env.curriculum.enabled: true`：前期减小 `penalty_action_rate` 等，避免未学会迈步就被压成僵硬站姿。
- 命令速度：前期可 CLI 限制 `env.commands.vel_limit=[[0.3,0,0],[0.5,0,0]]`，学会走再放开。

### 8.4 若 YAML 仍伸膝 / 侧摆：需改奖励（代码）

在摆动相（脚高目标 &gt; 阈值）增加例如：

- 惩罚 **髋 Roll 偏离 0**；
- 惩罚 **膝角 &lt; 默认弯膝**（伸膝）。

当前仓库 **尚无** 该项；要在 `K1WalkEnv` 增加 reward 项并在 owner `reward.scales` 里给系数。需要时可单独提需求实现 `penalty_swing_knee_extension` / `penalty_swing_hip_roll`。

### 8.5 调试时建议看的 log

- `reward/feet_phase`、`reward/penalty_feet_ori`、`reward/penalty_orientation`
- `reward/pose`、`reward/upper_body_pose`
- 关节曲线：索引 11/17（Hip_Roll）、13/19（Knee_Pitch）相对默认 0 / 0.3
